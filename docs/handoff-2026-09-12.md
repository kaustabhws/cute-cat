# Touch, drag and smooth motion — 12 September 2026

Requirements: CAT-07, CAT-08 and regression coverage for CAT-05/06 and NOT-01/02. The user's reported freeze and lag were real gaps in the earlier implementation; a passing pose/state test did not establish smooth playback or correct native release behavior.

## Changes

- `Companion` and new `PointerGesture`: separate press, pet, drag, landing and parking; preserve interaction deadlines across repeated settings/monitor refresh; resume walking promptly; recover after capture loss.
- `CatWindow`, `SpriteFrameCache`, `ArtPack`: background decoding/resizing, reusable native bitmaps/DC, bounded caching with obsolete size requests dropped; asynchronous WPF previews; exact native pointer handler path exposed to the test harness.
- Native pointer coordinates come from the dispatched mouse message (`GetMessagePos`), so dragging/context menus do not depend on permission to poll the global input-desktop cursor. Signed screen coordinates are retained.
- `FrameClock`: high-resolution Windows waitable timer, monotonic active deadlines, at most one queued UI frame. Idle/hidden cadence remains relaxed.
- `StateWriter` and UI refresh: serialized asynchronous atomic state saves and throttled status updates; no disk flush or PNG decode in the render tick.
- `assets/cat-v003`, `prepare_motion_v003.py`, prompts and provenance: original surprised pickup pose, soft landing, revised separately authored left/right gaits; 234 frame entries in 12 clips. The v002 reference and prior pack are retained.
- Packaging/launcher updated to `dist/CuteCat-0.3.0`. The app identifies its version and explains an already-running older instance rather than exiting silently.

## Checks and evidence

56 deterministic checks include 13 new pointer/recovery regressions. `--motion-smoke` calls the same pointer entry points as native messages and tests rendered greeting/drag/landing frames, resumed walking, capture recovery, warmed caches and measured cadence with the WPF cat preview visible. The existing 14-scenario native smoke still passes notification paw contact and cancellation. Hash/schema/alpha/timing/contact/documentation validation passes.

First measurement after caching still showed ~27 ms average dispatcher cadence. Replacing that timer measured walking 16.667 ms mean / 17.105 ms p95 and running 16.668 ms mean / 17.098 ms p95, with zero warmed gait cache misses. These are local frame-update measurements, not a guarantee of monitor presentation on every machine. Final results are in `art-previews/v003`.

The Windows UI helper again returned `GetCursorPos failed: Access is denied (0x80070005)` while trying to restore the old app. Thus physical mouse interaction was not automatically verified; supplied-coordinate tests and native rendering are labeled accordingly. The user's prior real-notification confirmation remains separate evidence. Broader DPI/hot-plug/Narrator validation is still release work.

No permission expansion, browser monitoring, paid feature or runtime image service was added. New artwork used the authorized Azure CLI, original reference only, neutral cat behavior, and no key persistence. See `art-source/provenance-v003.json` for source and prompt paths.
