## User-facing behavior

Your cat now contains Coat, Hats, Neckwear, Collars and Personality tabs, with a live companion preview. Coat offers eight swatches plus opaque six-digit custom RGB hex input. Hats include beanie, beret, sun hat, party hat and daisy; neckwear includes bandana, bow tie and scarf; collars include a plain band, bell and heart charm. Each slot has independent colour controls and None. Hats, neckwear and collars can be combined. Appearance is global across focus profiles; activity remains per-profile. Reset outfit & coat changes only appearance.

The old control affected only accessory colour; the body used hard-coded cream brushes. Coat colour now updates the body, head, tail and near legs together, with a related shadow on far legs and contrast-aware facial details for dark coats. Brush/pen colours are cached by coat value; the renderer does not allocate a new palette every frame. Changes paint immediately even when the normal frame rate is reduced. The preview and desktop use the same painter and pose contract.

Neckwear and collars are behind the chin; neckwear naturally occludes a collar under it. Bandana/scarf folds rest on the shoulder, not the face. Hats use the head transform, and the daisy follows the ear hinge. All artwork/animation remains original code and cubic paths. Thumbnail bitmaps are transient UI previews generated by that same painter, never runtime animation frames.

Dark theme uses charcoal-blue surfaces (`#171923`, `#222532`), warm text (`#F4F1EA`) and periwinkle accent (`#BBC1FF`). Light theme uses pale neutral/lavender surfaces with a deeper periwinkle accent. Main navigation, tabs, controls and pet/tray menus share the palette. Green remains available as an accessory colour, not the default UI accent.

Settings → Title bar colour offers Match app theme, Accent colour and Windows default. Windows 11's documented DWM caption/text colours are applied to native windows; resize, snap layouts, minimize/maximize and close buttons remain native. System preference changes refresh the app when following Windows, and high contrast restores native caption colours. No custom draggable imitation title bar is used.

Microsoft reference, checked 13 September 2026: [DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute), `DWMWA_USE_IMMERSIVE_DARK_MODE` (20), `DWMWA_CAPTION_COLOR` (35), `DWMWA_TEXT_COLOR` (36), and `DWMWA_COLOR_DEFAULT`. Caption/text colour are documented for setting; do not assume DwmGetWindowAttribute can read them back. The local QA verifies setter success and pixels from the application's own window render.

## Data and compatibility

0.9.1 control refinement: top navigation uses a separate template with no click/focus border; the selected page stays a filled rounded pill. WPF's keyboard-only focus visual is an underline, so keyboard focus remains identifiable without adding a mouse-click boundary. All TextBoxes use one rounded 9-pixel template with the native `PART_ContentHost`, themed caret/selection and a thin focus colour. Padding is applied once by the TextBox host; duplicating it as a ScrollViewer margin clips narrow fields. Light/dark exports were reviewed with focused navigation and `180` in the compact minutes input. The existing 12 appearance checks passed. No state/schema or permission change.

Schema 4 stores a `PetAppearance` record with coat plus three independent accessory slots/colours and a title-bar style. Schema 3 is preserved as `.schema3.json` before migration. Legacy flower/bandana/bow-tie/bell selections and their colour migrate to the appropriate slot. Existing nickname, theme, notification permission, profile rules, progress and history are preserved. Unknown colours/enums normalize safely; unknown future schemas remain read-only. The legacy fields are retained for compatibility with older fixtures but the appearance record is authoritative.

No new monitoring, app-closing permission, network classification or capture feature is introduced. Explicit `--appearance-checks` diagnostics render only this app's own HWND to verify its native caption. This is QA code, not a production observation loop.
